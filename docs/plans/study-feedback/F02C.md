## 2. Problem Description

A failed binding remains absent from the typed environment. Its uses produce dependent errors. A failed return also produces a missing-return error.

## 2b. Proposed Solution

Track binding failures in each lexical scope. Suppress errors that depend on a failed binding. Distinguish a syntactically present failed return from an absent return. Preserve independent statement and expression errors. Never lower a poisoned value into Core.

## 2c. Alternatives considered and rejected

Leave the limitation undocumented: authors cannot identify the contract boundary.
Combine unrelated fixes: a reviewer cannot verify one outcome independently.

## 2d. Acceptance Criteria

A failed call and its dependent receipt use produce one cause. An independent later mismatch remains visible. Cover branches, shadowing, nested expressions, and independent errors within an expression. A genuinely absent return retains its error.

## 2e. Test Plan

Golden: valid bodies remain unchanged. Edges: chained failed locals, branch scope, independent sibling expressions, failed return, and truly missing return. Known failure modes: poison escapes into Core or hides independent errors. Fuzz and stress: none; scoped deterministic cases suffice.
